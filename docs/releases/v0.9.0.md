# ARN Code v0.9.0 — Verified releases, safe installation and terminal rendering

## Upgrading: read this first

The install scripts now check every download against the release's
`SHA256SUMS` and manage installations through a manifest. Two things change
for existing installations:

**Windows**

- Installed with the install script of v0.7.0 or later: the existing
  `install-manifest.json` (a plain list of file names) is read, and the update
  runs as before. It is replaced by the new manifest format.
- Installed with the install script of v0.5 or v0.6: there is no manifest, so
  the update stops and lists the files it would replace. If they are ARN
  Code's, take them over once:

  ```powershell
  $env:ARN_ADOPT_EXISTING = "1"
  irm https://raw.githubusercontent.com/ARN-Forge/ARN-Code/main/scripts/install.ps1 | iex
  Remove-Item Env:\ARN_ADOPT_EXISTING
  ```

  (`-AdoptExisting` with a downloaded copy of the script). Only files with the
  names of the package's files are replaced and recorded; anything else in the
  directory is left alone.

**Linux and macOS**

- Earlier versions of `install.sh` did not record what they installed, so an
  existing `arn` without `.arn-install-manifest` is not replaced. If it is ARN
  Code, take it over once:

  ```bash
  curl -fsSL https://raw.githubusercontent.com/ARN-Forge/ARN-Code/main/scripts/install.sh | ARN_ADOPT_EXISTING=1 sh
  ```

  From then on the manifest records the installation, and later updates and
  uninstalls need no option.

**Older releases.** The install scripts refuse a release without a valid
`SHA256SUMS`. Releases before v0.9.0 have none, so they can no longer be
installed with the scripts (for example `ARN_VERSION=0.8.0` fails without
installing anything). Download them from their release pages instead.

## Added

### Release integrity

- **Build identity.** `arn --version` prints the version and the source
  commit, for example `arn 0.9.0 (1a2b3c4d5e6f)`. Local builds with
  uncommitted changes to tracked files add `-dirty`; builds without Git
  metadata report `(unknown)` unless the commit is passed with
  `-DARN_BUILD_COMMIT=<sha>`.
- **Release preflight.** A release run is refused before anything is built
  unless it is for a `vX.Y.Z` tag that matches the CLI and IDE versions and
  has release notes.
- **Package verification.** Every CLI archive (Windows x64, Linux x64, macOS
  arm64 and x64) is checked before it is published: exactly the expected
  entries, no links or paths outside the archive, and the extracted `arn`,
  run with a minimal environment, must report the tagged version and commit.
  The release build also runs the test suite in the same build tree.
- **Windows runtime.** The Windows CLI ZIP carries the Microsoft Visual C++
  runtime DLLs that `arn.exe` imports, copied unchanged (Microsoft-signed)
  from Visual Studio's redistributable folder, next to the OpenSSL DLLs. It
  runs on Windows 10 and 11 x64 without a separately installed Visual C++
  Redistributable. Windows Update does not service these app-local copies;
  they are updated with each ARN release.
- **`SHA256SUMS`.** Every release publishes the SHA-256 of each release file.
  The release job writes it and checks it with a second, independent tool
  before publishing. It detects damaged or mixed-up downloads; it is not a
  signature. The README shows how to check a manual download.

### Installation, updates and uninstall

- **Verified installs.** `install.ps1` and `install.sh` download the archive
  and `SHA256SUMS` from the same release and check the archive before
  extracting or running anything. A missing, malformed or mismatching entry
  stops the installation with nothing changed.
- **Choose a release.** `ARN_VERSION=X.Y.Z` (or `vX.Y.Z`), and `-Version` for a
  downloaded `install.ps1`, install that release instead of the latest.
- **Staged updates with rollback.** The new version is staged next to the
  installation and checked before it replaces anything. If an update fails,
  the previous files are put back; on Windows the user `PATH` is restored as
  it was. On Linux and macOS `arn` is replaced with a single rename, and a
  signal (for example Ctrl+C) also rolls back, with a non-zero exit status.
- **Recovery after interruption.** Each update writes a transaction record
  into the install directory. If an update is killed or loses power, the next
  run of the installer puts the previous installation back before doing
  anything else (an interrupted first installation is removed). Backups are
  deleted only after an update has completed. If recovery finds something it
  cannot account for, it stops and names it instead of forcing its way
  through, and keeps the record and the backup. On Windows this includes a
  file of yours where it would put a previous file back; on all platforms, a
  missing work directory or a manifest the installer cannot show it wrote.
- **Installation manifest.** Each installation records the files it owns
  (`install-manifest.json` on Windows, `.arn-install-manifest` on Linux and
  macOS). Only those files are ever replaced or removed; other files in the
  install directory are not touched.
- **Uninstall.** `ARN_UNINSTALL=1` (or `-Uninstall`) removes the files the
  manifest lists, the `PATH` entry or profile lines the installer added, and
  the install directory if it is then empty (on Linux and macOS only if the
  installer created it, so a shared `~/.local/bin` stays). It checks every file before
  removing any, reports files it could not remove (for example while ARN is
  running) and can simply be run again.
- **`PATH` and shell profile.** On Windows the user `PATH` keeps its registry
  type (`REG_EXPAND_SZ`) and other entries keep their text, order and
  `%VARIABLE%` references. On Linux and macOS the profile is edited by writing
  a new copy next to it and renaming it into place, keeping its permissions and
  a symbolic link to it; if it cannot be updated, `arn` is still installed and
  the line to add is printed.

### Terminal

- **Shared renderer.** The interactive UI uses one renderer on POSIX and
  Windows and runs on the alternate screen; on exit the conversation is
  printed once into normal scrollback. With redirected input or output on
  Windows, ARN writes plain append-only output.
- **Mouse wheel on Windows.** The wheel scrolls the conversation, also while a
  reply streams. Select text with Shift+drag in Windows Terminal, or
  Edit > Mark in the classic console window.

## Fixed and hardened

- Text from models, tools, providers and environment values is sanitized
  before it reaches the terminal: escape sequences and control characters are
  dropped and malformed UTF-8 is replaced, in plain output, the header and the
  status line.
- Console input: Esc and Ctrl+C cancel a draft, and stale input is discarded
  before a credential prompt appears.
- HTTP requests in progress can be cancelled reliably. ARN Core now supplies
  the single, patched copy of cpp-httplib, with per-request cancellation.
- CI runs a Linux Debug build with AddressSanitizer and UndefinedBehaviorSanitizer
  and the POSIX terminal suite on a real pseudo-terminal; skipped tests are
  reported as skipped.

## Compatibility and known limitations

- `ARN_TERMINAL_RENDERER` no longer selects a renderer; values other than
  `alternate` only produce a warning.
- `SHA256SUMS` is unsigned and published beside the archives; it does not
  prove who published a release.
- Two installers running at the same time into the same directory are not
  supported.
- Rolling back an interrupted update discards changes you made to files of
  the half-installed new version.
- On Windows, recovery from an interrupted update removes the install
  directory from the user `PATH` if that run had added it, even if you added
  the same entry yourself afterwards.
- The installers do not force records to disk. After a power loss the
  transaction record can be unreadable; the installer then stops, keeps every
  backup and explains how to put the previous files back by hand.
- On Linux and macOS, replacing the profile by renaming does not keep other
  hard links to it, and ACLs or extended attributes are not copied.
