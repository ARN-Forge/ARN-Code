# ARN Code v0.9.0 (prerelease, Linux and macOS) — Verified releases, safe installation and terminal rendering

## Release status: read this first

- **This is a prerelease.** It is not the latest stable release, and the
  standard install commands do not install it.
- **Platforms:** Linux x64, macOS Apple Silicon (arm64) and macOS Intel (x64).
  The release contains `arn-linux-x64.tar.gz`, `arn-macos-arm64.tar.gz`,
  `arn-macos-x64.tar.gz` and their `SHA256SUMS`.
- **Not included:** the Windows CLI, the Windows IDE (portable ZIP) and the
  Windows IDE installer. Those packages include Microsoft Visual C++ runtime
  files, and their redistribution has not been cleared yet. No date is set
  for Windows packages; on Windows, `ARN_VERSION=0.9.0` stops without changing
  anything.

**Install this prerelease** (Linux and macOS; on macOS run
`brew install openssl@3` first):

```bash
curl -fsSL https://raw.githubusercontent.com/ARN-Forge/ARN-Code/main/scripts/install.sh | ARN_VERSION=0.9.0 sh
```

`ARN_VERSION=0.9.0` must come after the `|`, directly before `sh`.

**Return to the stable release.** The installers never replace a newer
version with an older one unless you allow it, and naming the version is not
enough:

```bash
curl -fsSL https://raw.githubusercontent.com/ARN-Forge/ARN-Code/main/scripts/install.sh | ARN_ALLOW_DOWNGRADE=1 sh
```

## Upgrading an existing installation

The install scripts now check every download against the release's
`SHA256SUMS` and manage installations through a manifest.

**Linux and macOS:** earlier versions of `install.sh` did not record what they
installed, so an existing `arn` without `.arn-install-manifest` is not
replaced. If it is ARN Code, take it over once:

```bash
curl -fsSL https://raw.githubusercontent.com/ARN-Forge/ARN-Code/main/scripts/install.sh | ARN_ADOPT_EXISTING=1 ARN_VERSION=0.9.0 sh
```

From then on the manifest records the installation, and later updates and
uninstalls need no option.

**Windows (the install script, for stable releases):** this prerelease has no
Windows package, but the same new `install.ps1` installs stable releases.

- Installed with the install script of v0.7.0 or later: the existing
  `install-manifest.json` (a plain list of file names) is read, and the update
  runs as before. It is replaced by the new manifest format.
- Installed with the install script of v0.5 or v0.6: there is no manifest, so
  the update stops and lists the files it would replace. If they are ARN
  Code's, take them over once:

  ```powershell
  $env:ARN_ADOPT_EXISTING = "1"
  irm https://raw.githubusercontent.com/ARN-Forge/ARN-Code/main/scripts/install.ps1 | iex
  Remove-Item Env:\ARN_ADOPT_EXISTING
  ```

  (`-AdoptExisting` with a downloaded copy of the script). Only files with the
  names of the package's files are replaced and recorded; anything else in the
  directory is left alone.

**Releases without `SHA256SUMS`.** The install scripts refuse a release
without a valid `SHA256SUMS`. Earlier releases may not have one; download those
from their release pages instead.

## Added

### Release integrity

- **Build identity.** `arn --version` prints the version and the source
  commit, for example `arn 0.9.0 (1a2b3c4d5e6f)`. Local builds with
  uncommitted changes to tracked files add `-dirty`; builds without Git
  metadata report `(unknown)` unless the commit is passed with
  `-DARN_BUILD_COMMIT=<sha>`.
- **Release preflight.** A release run is refused before anything is built
  unless it is for a `vX.Y.Z` tag that matches the CLI and IDE versions, has
  release notes and a valid release platform policy for that version.
- **Release platform policy.** `release/platforms.json` in the tagged commit
  states which packages a release publishes; the workflow builds and publishes
  exactly those. A release that leaves out a platform must be a prerelease and
  is never made the latest release. For v0.9.0 it names Linux x64 and both
  macOS architectures.
- **Draft first, published by hand.** The release workflow creates a draft
  with exactly the policy's assets and their `SHA256SUMS` and never adds to or
  replaces an existing release. Publishing is a separate manual run that
  checks the draft's files against `SHA256SUMS` first, then checks that a
  prerelease did not become the latest release.
- **Package verification.** Every published CLI archive is checked before it
  is published: exactly the expected entries, no links or paths outside the
  archive, and the extracted `arn`, run with a minimal environment, must
  report the tagged version and commit. The release build also runs the test
  suite in the same build tree.
- **Minimum systems.** The macOS archives are built for macOS 15 (earlier
  releases needed the macOS version of the build machine, macOS 26 for Apple
  Silicon); they need Homebrew's `openssl@3`. The Linux archive is built on
  Ubuntu 24.04 and needs glibc 2.39, the libstdc++ of GCC 13 and OpenSSL 3
  (Ubuntu 24.04, Debian 13 or newer). The release build checks both limits.
- **Third-party notices.** Every archive of this release contains
  `THIRD-PARTY-NOTICES.txt`.
- **`SHA256SUMS`.** This release publishes the SHA-256 of each of its
  archives. The release job writes it and checks it with a second,
  independent tool before the draft is created. It detects damaged or
  mixed-up downloads; it is not a signature. The README shows how to check a
  manual download.

### Installation, updates and uninstall

- **Verified installs.** `install.ps1` and `install.sh` download the archive
  and `SHA256SUMS` from the same release and check the archive before
  extracting or running anything. A missing, malformed or mismatching entry
  stops the installation with nothing changed.
- **Stable by default.** Without `ARN_VERSION` the scripts install the latest
  stable release and never pick a prerelease. If it has no package for your
  platform or no `SHA256SUMS`, they install nothing and print the command for
  the newest release they could install; they never fall back to an older
  release by themselves.
- **Choose a release.** `ARN_VERSION=X.Y.Z` (or `vX.Y.Z`), and `-Version` for a
  downloaded `install.ps1`, install that release instead, a prerelease
  included.
- **Downgrade protection.** An installed newer version is not replaced by an
  older one unless `ARN_ALLOW_DOWNGRADE=1` is set; `ARN_VERSION` alone does not
  allow it.
- **Staged updates with rollback.** The new version is staged next to the
  installation and checked before it replaces anything. If an update fails,
  the previous files are put back; on Windows the user `PATH` is restored as
  it was. On Linux and macOS `arn` is replaced with a single rename, and a
  signal (for example Ctrl+C) also rolls back, with a non-zero exit status.
- **Recovery after interruption.** Each update writes a transaction record
  into the install directory. If an update is killed or loses power, the next
  run of the installer puts the previous installation back before doing
  anything else (an interrupted first installation is removed). Backups are
  deleted only after an update has completed. If recovery finds something it
  cannot account for, it stops and names it instead of forcing its way
  through, and keeps the record and the backup. On Windows this includes a
  file of yours where it would put a previous file back; on all platforms, a
  missing work directory or a manifest the installer cannot show it wrote.
- **Installation manifest.** Each installation records the files it owns
  (`install-manifest.json` on Windows, `.arn-install-manifest` on Linux and
  macOS). Only those files are ever replaced or removed; other files in the
  install directory are not touched.
- **Uninstall.** `ARN_UNINSTALL=1` (or `-Uninstall`) removes the files the
  manifest lists, the `PATH` entry or profile lines the installer added, and
  the install directory if it is then empty (on Linux and macOS only if the
  installer created it, so a shared `~/.local/bin` stays). It checks every file before
  removing any, reports files it could not remove (for example while ARN is
  running) and can simply be run again.
- **`PATH` and shell profile.** On Windows the user `PATH` keeps its registry
  type (`REG_EXPAND_SZ`) and other entries keep their text, order and
  `%VARIABLE%` references. On Linux and macOS the profile is edited by writing
  a new copy next to it and renaming it into place, keeping its permissions and
  a symbolic link to it; if it cannot be updated, `arn` is still installed and
  the line to add is printed.

### Terminal

- **Shared renderer.** The interactive UI uses one renderer on POSIX and
  Windows and runs on the alternate screen; on exit the conversation is
  printed once into normal scrollback. With redirected input or output on
  Windows, ARN writes plain append-only output.
- **Mouse wheel on Windows** (in the source; not part of this prerelease's
  packages). The wheel scrolls the conversation, also while a reply streams.
  Select text with Shift+drag in Windows Terminal, or Edit > Mark in the
  classic console window.

## Fixed and hardened

- Text from models, tools, providers and environment values is sanitized
  before it reaches the terminal: escape sequences and control characters are
  dropped and malformed UTF-8 is replaced, in plain output, the header and the
  status line.
- Console input: Esc and Ctrl+C cancel a draft, and stale input is discarded
  before a credential prompt appears.
- HTTP requests in progress can be cancelled reliably. ARN Core now supplies
  the single, patched copy of cpp-httplib, with per-request cancellation.
- CI runs a Linux Debug build with AddressSanitizer and UndefinedBehaviorSanitizer
  and the POSIX terminal suite on a real pseudo-terminal; skipped tests are
  reported as skipped.
- **IDE: no code from a CDN** (in the source; the IDE is not part of this
  prerelease). Earlier IDE releases loaded the Monaco editor from
  cdn.jsdelivr.net at run time, into the same window that talks to the
  backend, with no Content Security Policy. Monaco is now bundled; a strict
  Content Security Policy allows code only from the application; the window
  may only listen for events; and the project folder is chosen in a dialog
  shown by the backend, so the page cannot open an arbitrary folder. The
  unused shell plugin was removed. The IDE no longer needs the internet to
  show the editor.

## Compatibility and known limitations

- This is a prerelease for Linux x64 and macOS only. There is no Windows CLI
  or IDE package of v0.9.0; Windows users stay on the stable release.
- Going back from this prerelease to the stable release is a downgrade and
  needs `ARN_ALLOW_DOWNGRADE=1`.
- `ARN_TERMINAL_RENDERER` no longer selects a renderer; values other than
  `alternate` only produce a warning.
- `SHA256SUMS` is unsigned and published beside the archives; it does not
  prove who published a release.
- Two installers running at the same time into the same directory are not
  supported.
- Rolling back an interrupted update discards changes you made to files of
  the half-installed new version.
- On Windows, recovery from an interrupted update removes the install
  directory from the user `PATH` if that run had added it, even if you added
  the same entry yourself afterwards.
- The installers do not force records to disk. After a power loss the
  transaction record can be unreadable; the installer then stops, keeps every
  backup and explains how to put the previous files back by hand.
- On Linux and macOS, replacing the profile by renaming does not keep other
  hard links to it, and ACLs or extended attributes are not copied.
