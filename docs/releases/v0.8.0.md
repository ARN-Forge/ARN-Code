# ARN Code v0.8.0 — OmniRoute, ACP, and terminal reliability

## Added

- **Native OmniRoute provider.** Use `/provider omniroute` and the masked
  `/key-omniroute` prompt. The default endpoint is `http://localhost:20128/v1`;
  `ARN_OMNIROUTE_BASE_URL` is an optional override. `/status` displays the
  effective endpoint, and `/models` uses the server's catalog.
- **Kiro through ACP.** `/provider kiro` or `/acp kiro` starts an external
  `kiro-cli acp` session with streamed replies, model selection, permission
  requests, and cancellation. Install and authenticate Kiro CLI separately;
  it is not included in the release. `/acp off` returns to native-provider mode.

## Fixed and hardened

- Shared OpenAI-compatible provider infrastructure in ARN Core handles more
  streaming text and tool-call variants, streamed IDs/arguments, multiple tool
  calls, and provider errors. Unrecognized/empty responses no longer silently
  appear successful. OpenRouter continues to use the shared infrastructure.
- OmniRoute HTTP 400 `Invalid model` receives a clear account/session
  availability message. Catalog membership does not guarantee generation
  access; `kiro/` and `kr/` availability is backend-dependent. There is no
  hardcoded model allowlist.
- Windows keeps the bordered ARN header and Arny mascot while restoring normal
  terminal scrollback and terminal-owned mouse selection/wheel behavior.
  Confirmation input remains visible, with Backspace and Esc/Ctrl+C support.
- ACP permissions round-trip the exact server `optionId`. Repeated requests
  in one turn remain independent; cancellation, EOF, subprocess exit, and
  shutdown resolve pending requests without carrying stale permission state
  into another session.
- ACP subprocess ownership, pipe setup, exit checks, termination, and cleanup
  are supported across Windows and POSIX. Monitoring avoids reliance on
  `std::jthread`/`std::stop_token` availability in older Apple libc++.
- Deterministic terminal-input and ACP permission tests replace runner-dependent
  event injection/timing assumptions. Normal CTest uses fake ACP fixtures;
  real-Kiro smoke tests are optional and skip when unavailable.

## Compatibility and security

- Native provider keys remain in memory and are entered through masked prompts;
  persistent API-key storage is not included.
- Native file tools retain project-root/sensitive-file protections and explicit
  approval. Kiro is an external agent with its own tools, authentication, and
  security policy; ARN Code does not apply its native filesystem sandbox to
  the Kiro process. Approval covers permission requests the backend sends.
- Existing Explorer/Planner/Coder/Reviewer workflows are preserved. They use
  native providers rather than the external ACP session.
- The Windows IDE is versioned alongside the CLI; its agent panel still exposes
  Gemini and DeepSeek. OmniRoute and Kiro ACP are CLI integrations.
- ARN Core is pinned to
  [`4abac2a09f1ff887640948a55ee21c4f1b6c7ecd`](https://github.com/ARN-Forge/arn-core/commit/4abac2a09f1ff887640948a55ee21c4f1b6c7ecd).

## Downloads and installation

The release workflow builds these stable asset names:

- `arn-windows-x64.zip`
- `arn-linux-x64.tar.gz`
- `arn-macos-x64.tar.gz`
- `arn-macos-arm64.tar.gz`
- `arn-ide-windows-x64.zip`
- `arn-ide-windows-x64-setup.exe`

CLI installers use the latest published release; they will select v0.8.0 only
after it is published. See [installation instructions](../../README.md#install).
Windows archives include runtime DLLs. Linux/macOS need system OpenSSL libraries;
macOS uses `openssl@3`. The Windows IDE requires WebView2 and is unsigned.

Cross-platform CI covers Windows x64, Linux x64, macOS arm64, and macOS x64.
Offline build/tests do not establish live provider access or a working real
Kiro account/session.
